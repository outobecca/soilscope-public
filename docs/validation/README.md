# Reference checks and measured-data drop-in

SoilScope currently ships **one illustrative reference**, not a measured
validation dataset. The reference-check tab says so in the UI, and the CI gate
checks that the model still reproduces the committed illustrative pattern. It
is a regression gate, not evidence of field accuracy.

**Measured data is an external blocker.** Producing a real validation dataset
needs field or lysimeter observations at known depths and times with documented
uncertainty. Until such a dataset exists, the illustrative gate remains the
only accuracy check and no result may be described as field-validated (see
[Measured data: external blocker](#measured-data-external-blocker)).

The active reference is:

```
assets/validation/reference.json
```

No code changes are needed to replace it.

## What the gate does

`test/validation/illustrative_accuracy_test.dart` runs a fixed, plant-free
168-hour soil column (`ValidationReferenceRun`), samples the model at the
reference times, and computes NSE and RMSE for every series. It fails if any
metric crosses the threshold declared **inside the reference file**.
`test/validation/model_version_test.dart` additionally requires the file's
`model` block to match the current parameter fingerprint, so a solver constant
cannot change without a deliberate reference update.

Current illustrative thresholds:

| Series | NSE minimum | RMSE maximum | Unit |
|---|---:|---:|---|
| `waterContent@0` | 0.99999 | 0.00001 | m3/m3 |
| `nitrateContent@0` | 0.99999 | 0.00001 | mg/kg |
| `temperature@0` | 0.99999 | 0.00001 | K |

Run just the gate with:

```bash
flutter test --no-pub test/validation/
```

The thresholds are deliberately tight because this reference is generated from
the same model. A 5% change to the hydrology interface flux was shown to move
water NSE to 0.999923 and RMSE to 2.6e-4, which fails these tolerances. They are
**not** a claim that the model is within 1e-5 m3/m3 of reality.

## Model parameter fingerprint

The model-affecting constants in `lib/core/simulation_constants.dart` are
versioned by `ModelParameterSet`
(`lib/domain/models/model_parameter_set.dart`) as an `id`, a `version` and an
8-character fingerprint. Rendering and component-layout constants are
deliberately excluded, so a visual change does not invalidate a scientific
reference.

The fingerprint is recorded in three places:

- the saved session envelope (`simulation_session` → `model`),
- this reference file (`model`),
- Phase 4 profile captures (`model` in the JSON payload).

Print the current identity with:

```bash
dart run tool/model_version.dart
```

When a listed constant changes:

1. bump `ModelParameterSet.currentVersion`,
2. update the pinned fingerprint in `test/validation/model_version_test.dart`,
3. regenerate the illustrative values and update the `model` block in
   `reference.json`,
4. update the capture expectations in `PERFORMANCE.md`.

A save produced by a different parameter set still loads, but the mismatch is
logged with both labels; it is never silently presented as the current model.

## JSON schema

The fixture is one JSON object. Provenance lives beside the numbers.

```json
{
  "id": "unique_dataset_id",
  "kind": "illustrative",
  "source": "Where the data came from, with a citation or DOI.",
  "provenanceNotes": "Method, calibration, license, contact, limitations.",
  "sampling": "Depths, dates/intervals, and what each point represents.",
  "generatedBy": "Instrument/process and the script or person that produced it.",
  "model": {
    "id": "soilscope-core",
    "version": 1,
    "fingerprint": "8712a30f"
  },
  "relativeTimes": [0.125, 0.25, 0.5, 1.0],
  "series": [
    {
      "variable": "waterContent",
      "layerIndex": 0,
      "layerId": "A",
      "unit": "m3/m3",
      "values": [0.29, 0.27, 0.23, 0.20],
      "threshold": { "nse": 0.99999, "rmse": 0.00001 }
    }
  ]
}
```

`kind` must be `illustrative` or `measured`. The UI chooses its badge and
disclaimer from this field. An illustrative reference always displays:

> This reference is a synthetic pattern generated by SoilScope's own model,
> not measured field data. NSE and RMSE measure pattern agreement, not field
> accuracy.

A measured reference displays the source and sampling notes without that
disclaimer. Do not set `kind` to `measured` unless the series really are
observations.

### Times

Use **exactly one** of:

- `timesSeconds`: absolute times in seconds from simulation start. Use this for
  measured campaigns. Zero is allowed (the template starts at 0), but times
  must increase. Put the ISO dates and timezone in `sampling`.
- `relativeTimes`: fractions in `(0, 1]` of the current run. Use this only for
  synthetic patterns that are intended to scale with run length; zero is not
  valid here.

The number of `values` in every series must equal the number of times. Sampling
points outside the available run history are reported as a **coverage gap** in
the Reference Check tab and produce no metric; they are never clamped to the
first or last simulated state. The CI gate fails if any series is uncovered.
Run long enough to cover the reference, or adjust the reference times.

### Series

| Field | Meaning |
|---|---|
| `variable` | A variable supported by `ValidationFramework.extractTimeSeries`: `waterContent`, `nitrateContent`, `ammoniumContent`, `temperature`, `ph`, `microbialBiomass`, `lai`, and the other cases in that switch. |
| `layerIndex` | Zero-based index of the matching layer in the scenario's `SoilProfile`. Required for depth-resolved θ(z,t) and NO₃⁻ profiles. |
| `layerId` | Optional display label, e.g. `A` or `30–60 cm`. |
| `unit` | Unit of the values, shown in the UI and required by the loader. |
| `values` | Observations at the declared times, in the declared unit. No missing values; document any gap-filling in `provenanceNotes`. |
| `threshold` | `nse` (minimum) and `rmse` (maximum) for the CI gate. |

Add one series per variable per depth. For example, a measured profile can have
`waterContent@0`, `waterContent@1`, `nitrateContent@0`, and
`nitrateContent@1` in the same file. Results are keyed by
`variable@layerIndex`.

### Thresholds

The test reads `threshold` from the data, so replacing the reference also
replaces the gate. Set thresholds from the measurement's stated uncertainty and
the model's purpose:

- `rmse` should be no larger than the error that matters for the decision being
  taught or tested.
- `nse` must be above 0 for a meaningful comparison; negative NSE means the
  model is worse than the observed mean.
- Do not weaken a threshold to make a failing run pass. Fix the solver, or
  document why the reference/threshold was wrong.

The loader rejects a file with a missing source, provenance note, sampling
description, generation note, unit, threshold, duplicate series, or mismatched
value/time lengths. That is intentional: a silent loss of provenance is worse
than a failed load.

## Replacing the illustrative reference with measured data

1. Obtain layer-resolved volumetric water content θ(z,t) and/or nitrate NO₃⁻
   concentration observations at known depths and times. Record the site, soil,
   method, units, detection limits, timezone, license, and citation.
2. Put those observations into a copy of
   [`reference.template.json`](reference.template.json). Use
   `"kind": "measured"`, `timesSeconds`, and one series per variable/depth.
3. Set each series' `threshold` from the source's uncertainty and the decision
   the model is meant to support. Explain the choice in `provenanceNotes`.
4. Replace `assets/validation/reference.json` with your file. Keep the same
   filename. No Dart change is required; the repository points at that path.
5. Run `flutter test --no-pub test/validation/`. The test fails if any series
   is outside the run's simulated interval or outside the declared thresholds.
   If metrics are outside the thresholds, do not relabel the data as
   illustrative or loosen the gate silently: either fix the model or document
   why the reference or threshold is wrong.
6. Open the Reference Check tab and confirm it shows **MEASURED REFERENCE**, the
   citation, the sampling notes, and the declared gate.

`reference.template.json` has empty `values` on purpose, so it cannot be loaded
as if it were real data. It deliberately starts at 0 s to show that zero is a
valid absolute sample time; fill the values before use. The loader will reject
it until every series has one value per time.

## Regenerating the illustrative fixture

The illustrative values come from
`ValidationReferenceRun` in
`lib/domain/services/validation_reference_run.dart`. They are a frozen
regression reference, not a live output. Only regenerate them when a solver
change is intentional and reviewed, and record the reason in `provenanceNotes`.
Capture the eight sampled values from that run and update `reference.json`; do
not regenerate it as part of a normal fix.

## Measured data: external blocker

No measured dataset is bundled, and none can be produced from this repository
alone. A defensible dataset requires site, depth and time-resolved observations
with documented methods, units and uncertainty; synthesising one would be
fabrication. Until that external input arrives:

- the bundled reference stays `kind: "illustrative"`;
- the gate proves reproducibility and internal consistency, not field accuracy;
- the UI badge, README and any paper must say the same.

When data arrives, follow
[Replacing the illustrative reference with measured data](#replacing-the-illustrative-reference-with-measured-data)
and keep a `model` block in the new file so the comparison is tied to the
parameterisation that produced it.

## Phase 5 status and release gate

- The model parameter set is versioned and pinned; `reference.json` records
  the fingerprint it was generated with.
- `conservation_test.dart` covers water, mineral nitrogen and slow carbon
  across the reference run, interventions, scenario switches, pause/resume and
  persistence. `sensitivity_test.dart` checks directional responses to
  conductivity, temperature, initial water and initial nitrate.
- Measured observations remain an external blocker (see the section below).
- `tool/release_check.sh` runs the whole release path: model identity,
  analyzer, locale guards, full tests, validation gates, Phase 4 benchmarks and
  the web build. `SKIP_WEB=1` skips only the web build. The full suite includes
  the semantics and keyboard interaction tests, so the accessibility checks run
  on every release too.

## What this does not establish

This gate does not establish that SoilScope is validated against field
measurements. It establishes that the committed model still matches a
provenance-stamped illustrative pattern within the declared tolerances. Only a
`kind: "measured"` dataset with real observations, matching depths/times, and
defensible thresholds can support an accuracy claim. The conservation and
sensitivity tests in `test/validation/` show that pools stay physical and that
parameters move results in the expected direction; they are not calibration
evidence either.
